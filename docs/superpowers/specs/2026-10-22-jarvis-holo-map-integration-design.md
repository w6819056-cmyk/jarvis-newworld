# Jarvis 全息地图模块集成设计

## 目标

将 `E:\Projects\jarvis-holo-map` 中的地图应用并入 Jarvis Windows 安装包，作为 Jarvis 内可打开、可交互的地图模块。语音和输入框命令都通过现有 Codex 工具通道触发本地地图操作。

用户明确要求导航完全留在该地图项目中。高德地图 JavaScript API 是地图模块的底图和服务接口，不属于需要启动的外部导航软件；任何命令都不得打开高德客户端、默认浏览器或其他外部地图程序。

## 已核对的现状

- 地图项目是独立 Electron、React、TypeScript 应用。地图 UI 和交互集中在 `src/renderer/src/App.tsx`，包含地图初始化、定位、附近 POI、驾车/骑行/步行路线规划和沉浸地图视角。
- 地图项目另有 Electron 主进程、preload、HTML 入口、Vite 配置和 Electron Builder 配置。这些不能与 Jarvis 的宿主入口合并覆盖。
- Jarvis 的 `LocalTools` 已为 Codex Voice 和文本命令提供本地工具，并对参数作白名单校验。Jarvis 当前的透明 HUD 不适合承载完整可点击地图，因此地图应使用同一 Electron 应用中的独立窗口。
- 地图项目目前将高德 JS API Key 和安全代码写在 renderer 源码内，并有固定坐标定位回退。集成后不应把这些凭据留在源码或用固定坐标伪装当前定位。
- 地图当前“开始导航”实现会改变地图缩放、俯仰和朝向，以模拟沉浸视角；它不持续跟踪 GPS、不提供转弯语音指引，也不自动偏航重算。第一阶段复用并准确标示现有能力，不宣称提供实时车载导航。

## 方案比较

1. 单独启动现有地图程序：改动少，但需要额外安装和维护第二个进程，Jarvis 对窗口生命周期与命令结果的控制也较弱。
2. 将地图 renderer 集成为 Jarvis 的独立 BrowserWindow：保留地图界面和 Electron 应用边界，由 Jarvis 统一打包并通过受限 IPC 控制。推荐此方案。
3. 将地图重写进透明 HUD：会把地图交互与粒子/头盔 renderer 耦合，增加界面、权限和渲染风险，且会损失地图原有工作区。

## 设计

### 模块边界

在 Jarvis 内建立 `modules/holo-map` 地图模块，并将其 renderer 作为 Jarvis Vite 多页面构建中的第二个页面。Jarvis 主进程按需创建普通、有边框、可调整大小的地图 `BrowserWindow`，地图窗口使用独立 preload 和最小权限桥接接口。窗口关闭只关闭地图，不退出 Jarvis。

只纳入地图 renderer、地图组件、样式及运行需要的静态资源。不得复制地图项目的 Electron main、preload、`package.json`、锁文件、Vite/Electron Builder 配置、`node_modules`、构建目录、日志或现成安装包。Jarvis 保留自己的 Electron 入口、设置持久化和打包配置。所需依赖在 Jarvis 根包中明确声明，版本采用现有依赖或经过验证的兼容版本。

地图页面需要的远端高德 SDK、地图瓦片、定位和 API 请求要写入该页面专属的 CSP 白名单；不得放宽 Jarvis HUD 页面的 CSP。只向地图页面授权定位权限，按 Chromium/Electron 的实际定位权限行为处理用户拒绝和服务不可用。

### 命令与数据流

1. 用户说出指令或在 Jarvis 输入框提交文字，两种输入继续进入现有 Codex 会话和 `LocalTools` 工具调用链。
2. 新增有边界的地图工具：附近地点搜索，以及按目的地规划路线。参数限制长度；出行模式只允许驾车、骑行或步行等已支持选项；工具不得接受任意 URL、shell 命令或任意 IPC 通道名。
3. Jarvis 主进程打开或聚焦地图窗口，通过专用 `MapController` 将命令发送到地图 renderer，并等待带请求 ID 的结果。IPC 校验窗口来源、命令类型和参数；窗口关闭、超时、地图 SDK 未就绪时返回可理解的错误。
4. “附近有什么美食”默认使用设备当前定位，地图窗口打开后执行附近 POI 检索、绘制标记并显示列表；工具向 Codex 返回少量附近结果，供 Jarvis 简短播报。没有定位权限时明确提示，不使用旧地址或固定坐标兜底。
5. “导航到某地”默认从当前定位出发，先解析目的地，再在地图内规划路线并展示起终点、路线、距离和耗时；成功后调用地图已有沉浸视角。目的地存在多个候选时，显示有限候选并让用户选定后再规划。所有路线步骤都在该地图模块中完成，不调用外部软件。
6. 用户仍可直接在地图窗口使用原有地图交互和支持的功能。第一阶段由语音/文本明确控制 POI 搜索和路线规划，不把地图中的任意按钮、脚本或内部方法暴露为可调用工具。

### 凭据和本机数据

高德凭据保存在 Jarvis 本机用户设置中，不写入源文件、规格、日志、语音档案或 Codex 消息。主进程只通过地图专属 preload 将地图 JS API 初始化所必需的值交给地图窗口；这类 browser JS API 凭据最终会被 renderer 使用，应在高德控制台限制其可用范围。若现有凭据曾被发布或分享，应先轮换。此功能不向云端保存地图命令、位置或搜索记录。

### 失败处理

- 定位被拒绝、无可用位置或超时：保持地图打开并提示用户检查定位权限；不假装使用当前位置。
- 高德 API 未配置、SDK 加载失败或接口拒绝：显示具体的地图错误状态，并让 Jarvis 返回简短原因；不得静默切换到另一地图服务。
- 地点无结果或候选不唯一：不启动错误路线，显示结果或请求用户选点。
- 地图窗口关闭、renderer 崩溃或请求超时：清理未完成请求并返回失败，不阻塞 Voice 会话。

## 验收标准

- Jarvis 打包后能按需打开唯一的地图模块窗口，关闭地图不会退出 Jarvis。
- 语音与输入框的附近美食命令均能在地图上显示附近 POI，并让 Jarvis 返回有限结果摘要。
- 语音与输入框的导航命令均能在地图窗口内规划路线并进入现有沉浸地图视角；运行期间不会启动浏览器或外部地图软件。
- 模糊目的地需要用户选择；定位失败不会使用硬编码坐标。
- HUD 与地图窗口有各自受限的 CSP 和 preload 接口；地图错误会正常返回，不挂起命令。
- 高德凭据不在新增或修改后的源码中，命令、凭据和位置不进入云端档案。
- Jarvis 版本递增到 `0.3.30`；运行目标测试、`npm run windows:build`，并手工验证地图窗口、定位、附近搜索和路线流程。只在本地工作区构建，不推送云端。

## 暂不包含

完整 GPS 连续跟随、转弯语音播报、偏航检测与自动重算不属于本阶段，因为现有地图沉浸导航并不实现这些行为。之后若需要真正逐步导航，应单独设计并验证定位更新、后台权限、电量和路径偏离体验。
