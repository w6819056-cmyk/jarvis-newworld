# JARVIS HUD 多窗口结果面板设计

## 目标

在头盔附近提供钢铁侠/JARVIS 风格的结果 HUD。软件启动时不显示 HUD；每当一条语音或文本指令产生可展示的贾维斯结果时，创建一张新的 HUD 卡片。HUD 只显示贾维斯的结果，不重复显示用户原始指令；现有“本次识别”区域继续独立显示识别文本。

## 交互行为

- 首次有结果时，在头盔右侧显示第一张 HUD。
- 后续结果创建新的 HUD，并按创建顺序向下排列，不覆盖已有卡片。
- HUD 数量不设上限，不自动超时、不自动替换、不因新结果删除旧结果。
- 每张 HUD 都有独立关闭按钮；关闭只移除该卡片，其他卡片保留并重新排列。
- 卡片过多超出可视区域时，容器在头盔附近保持固定尺寸并允许滚动；页面本身不滚动，头盔和底部控制栏不被 HUD 遮挡。
- 关闭最后一张卡片后，HUD 容器隐藏。新结果再次产生时重新显示。
- Codex 回复流式到达时，当前指令对应的卡片实时更新；回复完成后保留最终内容。
- 错误、工具执行结果和天气结果都使用同一套 HUD 卡片，不打开浏览器显示结果。

## 天气结果

- 用户说出城市时，使用指定城市查询。
- 用户未说城市时，通过公网 IP 定位当前城市；用户说出城市时，直接使用指定城市。
- 天气查询作为受限本地工具执行，使用天气与地理编码 HTTP API 获取数据，结果直接返回给 Codex 和 HUD，不启动浏览器。
- 天气服务不可用时，HUD 显示明确的失败原因，不阻塞其他语音功能。

## 实现边界

- Renderer 维护有序 HUD 列表和稳定的卡片 ID；每张卡片只允许自己的关闭按钮删除。
- 主进程沿用现有 `AssistantState.reply` 流程，把最终/增量回复通过状态事件发送到 Renderer；无需改变现有对话记录格式。
- 新增天气工具时限制城市和查询长度，并对网络错误、超时和非法响应做统一错误处理。
- HUD 样式复用现有蓝青色视觉系统，使用半透明深色背景、细边框和轻微扫描/发光效果；不改变头盔、粒子和手势逻辑。

## 验证标准

- 启动后 HUD 不存在或不可见。
- 连续发送三条会产生回复的指令时，出现三张按顺序排列的 HUD。
- 关闭中间卡片只移除中间卡片，前后卡片仍保留并正确排列。
- 创建大量卡片时容器可滚动，头盔和控制栏位置稳定。
- 流式回复在对应卡片中更新，结束后内容保持。
- 天气请求不调用浏览器打开逻辑；指定城市和 IP 定位的当前城市都能显示结果，网络失败能显示错误。
