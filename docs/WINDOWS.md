# Windows 11 Jarvis

这是基于原项目的 Windows 独立入口。保留透明角色、聚合动画和光效；使用本地语音识别，将文字发给本机 Codex app-server，由 Windows 自带中文声音播报。原来的 macOS/Tauri 入口保持独立。

## 使用

1. 安装 Windows x64 版本的 Codex 并登录。Jarvis 复用该登录，不需要在界面里填写 API Key。
2. 安装并手动打开 Jarvis。安装包内已包含语音模型，正常使用不需要 Node.js、Python 或 Rust。
3. 状态显示“说‘嗨贾维斯’唤醒”后，说“嗨贾维斯，打开浏览器搜索今天的科技新闻”。也可以在底部输入指令。
4. 回复结束后 30 秒内可以继续说，无需重复唤醒。说“结束对话”回到待机。
5. 平时桌面显示原头盔。唤醒贾维斯后说“检查一下战甲”，或在同一句里说“嗨贾维斯，检查一下战甲”，即可显示全身模型并自动请求摄像头。也识别“检查战甲”“检查下战甲”“看一下战甲”等简短说法。张开手掌散开战甲部件，握拳组合；说“结束检查”返回头盔，无需再次唤醒。
6. 点击顶部聊天图标打开“对话与记忆”。聊天记录和长期记忆分别保存、搜索及清理；“记住我喜欢简洁的回答”会明确保存一条长期记忆，“我让你记住了什么”“忘记……”和“搜索以前的聊天……”由 Jarvis 本地处理。

战甲检查使用 MK46 模型保留的 47 个独立源部件；张手时零件向外散开，握拳时按原位置组合。该本地模型资源由用户提供，来源说明及使用限制见随包 `THIRD-PARTY-NOTICES.md`。

手势模式默认关闭。进入战甲检查会请求摄像头权限；也可以点击顶部“手势”进入检查或在摄像头失败后重试。画面仅在本机交给 MediaPipe 识别，不显示预览、不录制、不保存、不上传。右上角的状态提示在摄像头工作期间保持可见。暂时离开摄像头画面会保留战甲当前形态；关闭手势模式会立刻停止摄像头并组合战甲，语音说“结束检查”会返回原头盔。摄像头拒绝或发生错误时，模型仍显示且状态提示可用于重试。

打开软件、网页搜索、普通输入直接执行。创建、修改、覆盖、移动、重命名或删除用户文件前，助手会复述目标和更改，等待你说“确认”或“取消”。这由 Codex 的对话指令实现，并非系统级的文件写入拦截。程序正常运行产生的临时文件和缓存不逐项询问。发送消息、付款等对外生效的操作也须确认。

日常打开软件、网页和搜索提供直接调用 Windows 的工具，不需要为每个浏览器启动都执行命令审批。应用通过 PATH、开始菜单或明确的 exe 路径查找，没有固定应用名单。普通文本输入及更复杂的操作由 Codex 使用其可用工具完成；若它的原生规则仍要求审批，会显示具体内容，并支持“确认／取消”语音或按钮答复。不支持的协议请求会拒绝，不会自动同意。普通对话式提问则在下一轮语音中答复即可。

## 暂停、停止、退出

- 麦克风按钮：暂停监听并释放麦克风；恢复后重新监听唤醒词。
- 红色停止按钮 / Ctrl+Shift+空格：停止播报，尝试中断当前 Codex 回合，结束 Jarvis 管理的 Codex 进程树，回到待机。该快捷键只在 Jarvis 运行时注册。
- 执行和播报期间可以说“停止”或“贾维斯，停止”。必须等本地识别出完整短句；不能替代紧急按钮。此时其他语音不启动新任务，以避免同时执行多条误识别指令。
- 播报期间的自由打断、全双工自然对话尚未实现。停止后可重新唤醒发出新指令。
- 最小化后继续监听；右上角 ×、Alt+F4 会退出并关闭麦克风。不设置开机自启。

停止不能撤回已经发生的文件修改；已脱离 Codex 进程树的应用或后台服务可能继续运行。

## 设置及故障排查

- 工作目录必须是已存在的完整目录路径。每个目录保存自己的 Codex 对话编号；“新对话”仅切换编号，不删除历史。
- 找不到 Codex 时可指定 codex.exe 的完整路径；留空则先查找本机 Codex 安装，再查找 PATH。环境变量 JARVIS_CODEX_BIN 也可指定路径，错误路径不会静默回退。
- 语音不可用时仍可输入文字。检查 Windows 麦克风访问权限和默认录音设备，再点恢复监听或“重新加载语音”。不自动更改 Windows 隐私设置。
- 中文播报需要 Windows 桌面中文语音（例如 Microsoft Huihui Desktop）。可在设置中“试听声音”。缺少声音时显示错误，文字仍可使用。
- 语音模型使用 CPU，本地加载期间会有短暂等待；人声、口音、噪声和麦克风会影响识别质量。常见的唤醒词同音误识别已作兼容，但未做声纹验证。
- Codex 需要自身可用的模型配置、网络及账户权限。若登录失效，请在 Codex 中完成登录后重试。Jarvis 不读取或展示登录凭据。

### Jarvis 地图模块

地图由 Jarvis 主进程按需创建为应用内独立 `BrowserWindow`，与 Jarvis 一起构建和安装。它保留自己的地图界面和 renderer 边界，通过地图专属 preload 与受限 IPC 接收 Jarvis 的附近搜索和路线规划命令；不启动第二个 Electron 主进程、独立地图软件或外部浏览器。关闭地图窗口不会关闭 Jarvis。

首次使用时，在 Jarvis 设置里填写高德地图 JS API Key 和安全密钥。凭据保存在 Jarvis 本机设置文件，只提供给地图 renderer 初始化高德 SDK；请在高德控制台限制 Key 的可用范围。地图只申请当前位置权限，不申请摄像头或麦克风。说“帮我看看附近有什么美食”“附近咖啡馆”会打开或聚焦地图并显示 POI；说“导航到郑州东站”会在地图窗口内解析目的地并规划路线。若目的地有多个候选，需在地图中点选；当前位置不可用时，Jarvis 会提示检查 Windows 定位权限，不会使用固定坐标替代。

### Mineradio 本机连接

在设置的 `Mineradio.exe 位置` 填入 Mineradio 安装路径中的 `Mineradio.exe`。之后说“打开音乐播放器”会启动或唤起它；播放、暂停、切歌、音量、当前曲目和搜索播放通过随机一次性令牌认证的 Windows 命名管道连接。此控制桥只允许固定播放器操作，不提供 shell、任意脚本或文件操作。搜索结果不唯一时会返回候选项并要求补充歌名或平台。

本地源码联调可运行 `node --import tsx scripts/check-mineradio-dev-bridge.mjs <Mineradio 源码目录>`。该脚本会启动一次 Electron 开发实例、完成握手、读取当前播放状态后关闭它，不会修改播放队列。

权限采用 danger-full-access + on-request + user reviewer，并检查服务器返回的实际配置。它允许当前 Windows 用户有权限的本地操作，仍受系统/UAC 边界限制。on-request 不保证每个有风险的命令都会被服务器拦截。

原始音频只在内存里用于本地识别，不录音保存；待机转写不保存。最终任务文本会交给 Codex；Codex 处理任务所需的上下文和历史遵循其自身配置，不能将整条链路称为离线运行。

## 本地聊天档案和记忆

- Jarvis 将对话双方最终文字与元数据保存在 `%APPDATA%\\jarvis-codex\\conversation-memory.sqlite`。不保存音频、分段转写或生成语音。Codex Voice 使用 app-server 的 `thread/realtime/transcript/done` 最终文本通知；该协议没有稳定转写事件 ID，因此 Jarvis 只能抑制紧邻的完全相同转写，不能宣称跨重启的事件级去重。
- 长期记忆只由明确的“记住……”命令创建。未安装/加载本地语义模型时仍可使用关键词搜索。
- 本地 ONNX 语义模型为固定 revision `Xenova/bge-small-zh-v1.5`，安装包随附模型文件。开发构建需要先运行 `npm run windows:model`，下载器会校验 SHA-256；程序运行时不联网获取模型。
- Codex 可通过限量的本地工具按需搜索记忆与聊天档案。返回的文字进入当前活动 Codex 回合，其余未命中的档案不会自动发送。
- 在“对话与记忆”面板中可逐条删除一段聊天或一条记忆，也可分别清空聊天档案和长期记忆。清空 Jarvis 档案不会删除 Codex 原生线程。

# Windows 语音引擎

## 前台应用控件试点

Jarvis 现在提供受限的 Windows UI Automation 试点。Codex 可调用 `jarvis_inspect_foreground_ui` 读取当前前台窗口的控件角色、名称、可用状态和支持的单步动作，再调用一个 `jarvis_ui_*` 工具执行一次操作并核验结果。控件编号只在当前 Jarvis 进程内有效 30 秒；切换前台窗口后必须重新检查。

首阶段支持 `invoke`、非密码文本框的 `set_value`、`select` 和有限 `scroll`。输入最多 2000 个字符，检查最多返回 200 个控件。Jarvis 不读取密码值、不操作后台窗口、不使用坐标点击或任意 PowerShell，不处理保存/覆盖/删除文件、发送、付款和系统设置。动作未核验时会返回失败，不会声称成功。

记事本试点示例：打开记事本后说“检查当前窗口”，再让 Codex 找到编辑框并输入不需要保存的临时文本；需要保存文件时仍走现有确认流程。某些管理员权限窗口或自绘界面可能不暴露可访问控件，试点会提示重新检查或不支持，不会自动退回鼠标坐标操作。

Windows 集成检查默认跳过。显式运行 `$env:JARVIS_UIA_NOTEPAD='1'; npx tsx --test tests/windows-ui-automation-notepad.test.ts` 会启动一个空白记事本进程并检查控件树；若系统版本公开可写的非密码编辑控件，才填入未保存的测试文本并核验长度。测试关闭本次启动器创建的进程，不接触其他记事本窗口或磁盘文件。Windows 11 新版记事本可能只公开只读 `Document` 控件，此时检查通过但不会尝试键盘注入。

Windows 版设置中提供三种语音引擎：

- **Codex Voice**：使用原项目同款 Codex Voice v3/WebRTC。需要安装并登录支持 `realtime_conversation` 的 Codex，并在系统中允许 Jarvis 使用麦克风。
- **本地语音**：使用本地 sherpa-onnx 识别和 Windows 语音播报，默认兼容旧配置。
- **豆包语音**：使用 V3 WebSocket 实时 ASR/TTS，设置中保存 API Key、ASR 资源标识、TTS 资源标识和音色。豆包连接失败时会显示服务端错误，不会回退到本地语音。

选择 Codex Voice 后，渲染进程创建 WebRTC 麦克风连接，主进程通过本机 `codex app-server --enable realtime_conversation --listen stdio://` 调用 `thread/realtime/start`。SDP answer 通过 `thread/realtime/sdp` 事件返回，工具调用和审批仍沿用现有 Codex 会话。

语音引擎切换会先停止旧引擎并释放麦克风，任意时刻只有一个引擎可以采集音频。

豆包 ASR 推荐资源标识为 `volc.seedasr.sauc.duration` 或 `volc.seedasr.sauc.concurrent`，音频上行格式为 16kHz、16bit、单声道 PCM。API Key 只在 Electron 主进程使用。
